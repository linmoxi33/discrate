# discrate

把一堆命名混乱的音乐文件，整理成整齐、可回滚的音乐库。

一条命令，不需要写配置文件：

```bash
discrate ~/Downloads/音乐
```

它会先给你一份**方案**，你确认之后才动手；源文件一个字节都不改；不满意可以一条命令撤回。

---

## 为什么需要它

`beets` 是这个领域最强的开源工具，功能确实强 —— 自动匹配、插件生态、查询语言、转码、统计，一应俱全。但它的复杂度也是真的：

| 事实 | 数字 |
| --- | --- |
| 默认配置文件行数 | 207 行 |
| 默认配置项 | 约 90 个键 |
| 其中 `match.distance_weights` 一项的子权重 | 20 个 |
| 内置插件 | 74 个 |
| 单次导入需要理解的交互动作 | 6 种（`A`/`M`/`S`/`U`/`T`/`I`） |
| 路径模板语法 | `$albumartist/$album%aunique{}/$track $title` |

这些设计对「每天整理几百张专辑的收藏家」是效率工具，对「只想把下载文件夹理干净」的人是纯负担。更麻烦的是，默认配置里有几处会**直接坑到普通用户**，我们用真实文件实测过：

1. **`albumartist` 不会从 `artist` 继承。** 一个标签齐全的 MP3（歌手/专辑/曲名/轨号都有），只要没单独写 `albumartist`，就会被扔进 `Non-Album/` 目录。
2. **没有标签的文件会全部撞到同一个名字。** 三个无标签文件，`Item.destination()` 全部返回 `Non-Album.mp3` —— 如果真执行移动，它们会互相覆盖。
3. **`Item.destination()` 在专辑型文件上会选错模板。** 因为 `singleton` 这个查询对 `Item` 恒为真，`paths.default` 永远轮不到。这个语义错位藏在一个看起来通用的 API 后面。
4. **文件名合法化不处理 Windows 保留名。** `CON.mp3`、`NUL.mp3` 这类名字在 Windows 上根本建不出来，但工具会照常规划。
5. **`sanitize_path()` 是给路径片段用的。** 传 `AC/DC` 进去，得到的是 `AC\DC`（两级目录），不是 `AC_DC`。

`discrate` 的做法是：**保留 beets 的能力，重做它的默认值和交互**。

## 上手

### 安装

```bash
pip install discrate
```

需要 Python 3.10+。首次运行会自动创建隔离的 beets 配置目录，不会读也不会改你已有的 `~/.config/beets/config.yaml`。

### 三步走完

```bash
# 1. 先看方案（只读，不动任何文件）
discrate plan ~/Downloads/音乐

# 2. 确认没问题，执行
discrate ~/Downloads/音乐

# 3. 后悔了，撤回
discrate undo --target ~/Downloads/音乐/整理结果
```

第 2 步会先把方案打出来，问一句「继续？[Y/n]」，你回车才动手。

## 它到底做了什么

### 整理前

```
音乐/
├── 01.mp3
├── 02 - 晴天.mp3
├── 周杰伦 - 稻香.mp3
├── 稻香 - 副本.mp3
├── 完整标签.mp3
├── AC-DC - Back In Black.mp3
├── 空文件.mp3
├── readme.txt
├── 周杰伦 - 叶惠美/
│   ├── 夜曲.mp3
│   └── 03 以父之名.mp3
└── 同名不同码率/
    └── 晴天.mp3
```

### 整理后

```
音乐/整理结果/
├── AC_DC/Back_In_Black/01 Hells _Bells__.mp3
├── 单曲/周杰伦/稻香.mp3
├── 单曲/未知歌手/东风破.mp3
├── 单曲/未知歌手/晴天.mp3
├── 周杰伦/叶惠美/03 以父之名.mp3
└── 周杰伦/叶惠美/夜曲.mp3
```

同时会告诉你：`01.mp3` 因为文件名只有数字、标签也没有曲名，没法整理；`稻香 - 副本.mp3` 与 `周杰伦 - 稻香.mp3` 逐字节相同，没有重复复制；`空文件.mp3` 是 0 字节。

### 每个判定都有理由

方案里每个文件都能回答「为什么这么处理」：

```
  建议复核（仍会整理，但信息不足，建议确认后再执行）
    同名不同码率\晴天.mp3
      - 从文件名/目录名补全：曲名←文件名
      - 找不到歌手信息，归入「未知歌手」
      - 信息不足，建议人工确认后再整理

  判定为重复的（不复制）
    稻香 - 副本.mp3
      - 与 周杰伦 - 稻香.mp3 内容完全相同（逐字节一致）
```

注意「曲名←文件名」这种标注 —— 它明确告诉你这个字段是**推断出来的**，不是文件自带的。判断能不能信，决定权在用户手上。

### 三档置信度

| 置信度 | 含义 | 处理 |
| --- | --- | --- |
| 高 | 关键字段全部来自文件标签 | 直接整理 |
| 中 | 部分字段来自文件名 | 直接整理 |
| 低 | 歌手缺失，归入「未知歌手」 | 仍会整理，但列进「建议复核」 |

低置信度的文件**不会被悄悄丢掉**，也不会被塞进一个编造的歌手名 —— 路径里明写「未知歌手」，标签里不写，用户一眼能看出哪些还需要补。

## 四条安全承诺

### 1. 源文件不动

默认 `copy` 模式：只往 `整理结果/` 复制，源目录里什么都不改。想省空间可以用 `--mode move` 或 `--profile inplace`，但那是显式选择。

### 2. 一切可回滚

每条写操作都先落 journal 再动手：

```json
{"v": 1, "op": "copy", "src": "...", "dst": "...", "sha256": "...", "size": 9052}
{"v": 1, "op": "tag", "path": "...", "fields": {"artist": "周杰伦"}, "sha256_after": "..."}
```

`undo` 按逆序撤回。撤销时只删**内容哈希仍然匹配**的文件 —— 如果用户事后自己改过那份副本，宁可留着也不误删。

### 3. 反复运行不会重复整理

`整理结果/.discrate/state.json` 记录每个源文件整理到了哪里。第二次运行只处理新文件，不会产出 `(2)` `(3)` 一堆副本。

如果源文件内容变了（哈希不同），会重新整理；如果目标文件被删了，也会重新整理。

### 4. 不覆盖已有文件

目标位置已有同名文件时，默认**跳过并说明原因**，绝不覆盖。同一批次内两个文件渲染出同一个目标名时，后来者自动加 ` (2)`。

## 保留的高级选项

复杂度没有消失，只是从「必须理解」变成「需要时才看」：

| 参数 | 用途 |
| --- | --- |
| `--profile safe\|library\|inplace` | 换整理档位（默认 `safe`） |
| `--mode copy\|move` | 覆盖档位的处理方式 |
| `--output DIR` | 指定输出目录 |
| `--paths` 风格模板 | 模板支持 `{字段}` 和 beets 的 `$字段` 两种写法 |
| `--no-dedupe` | 关掉重复判定，每个文件都整理 |
| `--no-tag-write` | 只整理文件，不补写标签 |
| `--max-files N` | 本次最多处理多少个文件 |
| `--json` | 机器可读输出（只读语义，不会执行） |
| `-v` | 显示每条判定的理由 |
| `--dry-run` | 等价于只看方案 |

档位里的路径模板可以直接改：

```bash
discrate ~/音乐 --profile library
# 专辑路径变成 {albumartist}/{year} - {album}/{disc:02d}-{track:02d} {title}
```

模板语法：

- `{albumartist}/{album}/{track:02d} {title}` —— 推荐写法
- `$albumartist/$album/$track $title` —— beets 老写法，会自动翻译
- `%aunique{}` / `$if{}` 这类函数语法**不支持**，会明确报错而不是静默产生错路径

字段没有值时，它在路径里占的那一段会被**整段移除**，而不是留下 `//` 或 `00`。

## 与 beets 的关系

`discrate` 是 beets 之上的编排层，不是 fork：

- **借用**：标签读取（`Item.from_path`）、文件名合法化（`sanitize_path`）、音频格式支持
- **不用**：`Item.destination()` —— 理由见上面第 3 条，以及 [`docs/UPSTREAM-NOTES.md`](docs/UPSTREAM-NOTES.md)
- **自己实现**：专辑分组、路径决策、去重（含跨批次）、冲突消解、置信度分级、journal/undo、报告渲染

边界写在 [`docs/LIMITS.md`](docs/LIMITS.md) 里。
