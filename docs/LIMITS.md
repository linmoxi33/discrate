# 能力边界

写清楚「不做什么」，比写「能做什么」更能建立信任。以下每条都是刻意的取舍。

---

## 联网是可选，且只产建议

`discrate` **默认不联网**。加 `--lookup` 才会查询 MusicBrainz，并且：

- 查询结果只出现在方案和报告里，标着匹配度
- **不写入任何标签，不影响任何落盘决策**
- 只查「标题或歌手不是来自标签」的文件
- 结果落本地缓存，同一首歌第二次零请求
- 默认最多查 20 个（`--lookup-limit` 可调），受上游 1 次/秒限速约束

不做 AcoustID 音频指纹。理由是它需要额外安装 `fpcalc` 二进制，与「装完就能用」冲突。

代价：文件名全是 `track01.mp3`、标签又全空的文件，即使用 `--lookup` 也很难匹配上 —— 查询本身需要一个可用的标题或歌手作为输入。

---

## 封面只做「归位」，不做「补全」

- 不下载封面
- 不写入音频文件的内嵌封面（只复制 `cover.jpg` 这类外部文件）
- 不压缩、不缩放、不转换格式

归属规则刻意保守：**一个源目录必须唯一对应一个专辑，封面才会被采用**。根目录或杂项目录里混放的封面一律不用。非标准文件名只在目录内仅此一张图时采用 —— 一整个目录十几张扫图时随便挑一张，比没有封面更糟。

---

## 不做转码、不拆 CUE

- 文件格式保持原样，不转码、不改码率
- 不处理 CUE + 整轨：单个大文件 + CUE 分轨的组合无法拆分
- 不处理多碟合并、不处理内嵌多流

---

## 标签写入的范围

只写**从文件名/目录名推断出来、且原标签没有的**字段，范围限定在：

`artist` / `albumartist` / `album` / `title` / `track` / `year`

不会写 `genre`、`comment`、`composer`、`lyrics`，也不会覆盖任何已存在的标签值。在线建议即使命中，也不会被写进标签。

**标签修改不可回滚。** `undo` 能撤回文件复制/移动，但撤回不了已经写进副本的标签 —— 因为原始标签值没有留底。由于默认是 copy 模式，源文件的标签始终是安全的。

---

## 目录名推断的两条保守规则

1. **根目录名不参与推断。** 用户给的文件夹叫「下载」「我的收藏」还是「音乐」，都不能当专辑名。
2. **只有一个音频文件的目录，目录名不参与推断。** 一个文件待在 `同名不同码率/` 里，这个目录名显然不是专辑名。宁可走 `单曲/` 路径，也不要把文件塞进一个不存在的专辑。

第 2 条会带来一个副作用：`叶惠美/东风破.mp3`（单曲目专辑）不会被归入 `叶惠美` 专辑，而是进 `单曲/未知歌手/`。这是刻意的 —— 猜错专辑比不猜更麻烦。

---

## 模板语法

支持：

- `{albumartist}/{album}/{track:02d} {title}`（推荐）
- `$albumartist/$album/$track $title`（beets 老写法，自动翻译）
- 任意 Python format spec（`{track:02d}`、`{year}`）

不支持：

- `%aunique{}`（专辑名去重括号）
- `$if{}` / `${}`（条件与函数）
- 查询式路径规则（`paths: { 'singleton:true': ... }`）

遇到不支持的语法会**直接报错**，不会静默降级 —— 静默产生错路径比报错危险得多。

---

## 文件类型

只处理这些扩展名：

`.mp3` `.flac` `.m4a` `.mp4` `.ogg` `.oga` `.opus` `.wav` `.wma` `.aiff` `.aif` `.ape` `.wv` `.mpc` `.dsf` `.dff`

其他文件（含 `readme.txt`、`cover.jpg`、`.DS_Store`）一律忽略，并在报告里计数。

---

## 其他限制

| 项 | 说明 |
| --- | --- |
| 文件名长度 | 单段上限 120 字符（可配置），超长截断并在报告里标注 |
| 路径总长 | 未特殊处理 Windows 260 字符限制；深层嵌套目录可能失败，失败项会进「失败清单」而不是中断整批 |
| 符号链接 | 不跟随（`os.walk(followlinks=False)`），避免循环 |
| 跨盘移动 | `--mode move` 跨盘时退化为「复制 + 删除源」，速度慢但行为正确 |
| 隐藏文件 | 以 `.` 开头的文件与目录一律跳过 |
| 并发 | 单线程顺序执行；同一条目失败不影响后续条目 |
| 撤销范围 | 只撤销本工具创建/移动的文件；用户事后修改过的副本会被保留并说明原因 |

---

## 与执行相关的边界

| 项 | 说明 |
| --- | --- |
| 源文件变更 | 执行前逐字节复核；方案生成后被改动的文件会跳过并说明，不会按旧计划落盘 |
| 封面撤销 | `undo` 会把复制过去的封面一并删除 |
| 报告文件 | `整理报告.md` / `整理报告.json` 放在输出目录根部，不在 `.discrate/` 里，方便直接打开 |
| 目录树上限 | 预览默认 3 层、每层 6 项；报告放宽到 6 层、每层 100 项；超出都会明示「还有 N 项」 |
