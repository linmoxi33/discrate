# 更新日志

## 0.2.0 — 2026-10-22

v0.1 是一个能跑通的安全整理器。这一版补的是「用户实际会缺的东西」，不是堆功能。

### 新增

**整理前就能看到结果长什么样**

方案顶部增加目录树预览，层数与每层条目有上限；超出会写「… 还有 N 项」，而不是假装只有几条。表格加了「置信」列，高/中/低一眼可见。

**整理报告落盘**

输出目录生成 `整理报告.md` 与 `整理报告.json`：结构树、逐条明细（置信度 + 理由）、重复判定、无法处理的文件、失败清单、撤回命令。终端输出看过就忘，报告可以留档。

**专辑封面跟着走**

`cover.jpg` / `folder.jpg` 会被放到对应专辑目录。保守规则：**一个源目录必须唯一对应一个专辑，它的封面才被采用**。根目录或 `下载/` 里混放的封面归属不明，宁可不用。非标准文件名（如 `扫描0001.jpg`）只在目录里仅此一张时采用。

**方案与执行之间的源文件校验**

执行前逐字节复核源文件哈希。文件在生成方案后被改动或删除，该条跳过并说明，不会把陌生文件按旧计划落盘。

**可选在线元数据建议（默认关闭）**

`--lookup` 打开。守住三条：只产建议绝不写盘、只查信息不足的文件、结果落本地缓存（同首歌零重复请求）。受 MusicBrainz 1 次/秒限速约束，默认最多查 20 个。仅用标准库 `urllib`，无新增依赖。

**进度反馈**

大目录时显示 `[137/500] 27% · 已用 12秒 · 剩约 33秒 · 文件名`，按时间与百分比双重节流。

### 修复

- `undo` 撤回数量此前只统计音频，加入封面后计数正确
- 目录树与表格的超长行按显示宽度截断（中日韩字符计 2 列）

### 测试

| --- | --- | --- |
| pytest 用例 | 157 | **224** |
| 定向变异体（全部杀死） | 15 | **23** |
| 普通用户可用性检查 | 18 项 | **24 项** |

新增变异体覆盖：封面分配、封面归属校验、封面的撤销、源文件一致性、报告文件名、在线查询上限、缓存落盘、目录树溢出提示。

## 0.1.0 — 2026-10-22

首个版本。beets 的面向普通用户重设计：3 档默认值、三档置信度、字段来源可解释、journal/undo、跨批次去重。

修正的上游问题（详见 `docs/UPSTREAM-NOTES.md`）：`albumartist` 不继承 `artist`、无标签文件全部撞名、`Item.destination()` 对专辑型文件选错模板、`sanitize_path()` 只适合路径片段、Windows 保留名、尾部点空格、组件长度。
