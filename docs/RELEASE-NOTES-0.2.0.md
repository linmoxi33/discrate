## discrate 0.2.0

把一堆命名混乱的音乐文件，整理成整齐、可回滚的音乐库。

0.1 是一个能跑通的安全整理器。0.2 补的是用户实际会缺的东西 —— 不是堆功能。

### 新增

**整理前就能看到结果长什么样**

方案顶部先给一棵目录树。层数与每层条目都有上限，几千首不刷屏；超出会写「… 还有 N 项」，而不是假装只有几条。表格加了「置信」列，高/中/低一眼可见。

```
  整理后的结构
    单曲/
      周杰伦/
        稻香.mp3
      未知歌手/
        东风破.mp3
```

**整理报告落盘**

输出目录生成 `整理报告.md` + `整理报告.json`：结构树、逐条明细（置信度 + 理由）、重复判定、无法处理的文件、失败清单、撤回命令。终端输出看过就忘，报告可以留档。

**专辑封面跟着走**

`cover.jpg` / `folder.jpg` 落到对应专辑目录，播放器里不再是一片灰方块。

保守规则：**一个源目录必须唯一对应一个专辑，它的封面才被采用**。根目录或 `下载/` 里混放的封面归属不明，贴到哪张专辑上都是瞎猜 —— 宁可不用。非标准文件名只在目录内仅此一张图时采用（一整个目录十几张扫图，随便挑一张比没有更糟）。

**方案与执行之间的源文件校验**

执行前逐字节复核源文件哈希。生成方案后被改动或删除的文件直接跳过并说明，不会把陌生文件按旧计划落盘。

**可选在线元数据建议（默认关闭）**

`--lookup` 打开。守住三条：

1. 只产建议，**绝不写盘** —— 匹配结果出现在方案和报告里，标着匹配度
2. 只查信息不足的文件（标题/歌手不来自标签的）
3. 结果落本地缓存，同一首歌第二次零请求

受 MusicBrainz 1 次/秒限速约束，默认最多查 20 个（`--lookup-limit` 可调）。仅用标准库 `urllib`，无新增依赖。

**进度反馈**

`[137/500] 27% · 已用 12秒 · 剩约 33秒 · 文件名`，按时间与百分比双重节流。

### 修复

- `undo` 撤回计数此前只统计音频，加入封面后计数正确
- 超长行按显示宽度截断（中日韩字符计 2 列）

### 验证

| 项 | v0.1 | v0.2 |
| --- | --- | --- |
| pytest 用例 | 157 | **224** |
| 定向变异体（全部杀死） | 15 | **23** |
| 普通用户可用性检查 | 18 项 | **24 项** |
| CI | 9 job 绿 | 9 job 绿（ubuntu/windows × py3.10–3.13 + mutation） |

变异测试比的是「杀掉哪些变异体」而不是覆盖率：把某一行逻辑改坏，测试必须红。本版新增的 8 个变异体覆盖封面分配、封面归属校验、封面撤销、源文件一致性、报告文件名、在线查询上限、缓存落盘、目录树溢出提示。

可用性检查模拟零知识用户只按 README 的命令走完整链路：plan → 回车确认 → 检查结果（含封面与报告）→ 再跑一次确认无 `(2)` 副本 → undo（含封面）→ 撤回后重新整理。

### 边界

不联网时完全离线可复现；开 `--lookup` 也只查询不写盘。不做转码、不做 AcoustID 指纹、不拆 CUE、不下载封面、不写内嵌封面。详见 `docs/LIMITS.md`。

### 升级

v0.1 → v0.2 无需迁移。已有的 `.discrate/state.json` 与 journal 格式未变，`undo` 仍可撤回 0.1 产生的整理记录（0.1 没有封面记录，因此不会误删）。
