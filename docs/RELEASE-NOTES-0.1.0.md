## discrate 0.1.0

把一堆命名混乱的音乐文件，整理成整齐、可回滚的音乐库。

`beets` 是这个领域最强的开源工具，但它的默认配置有 207 行、约 90 个键，74 个插件，单次导入要理解 6 种交互动作。对「只想把下载文件夹理干净」的人来说，这些是纯负担 —— 而且它的默认值有几处会直接坑到普通用户（实测记录见 `docs/UPSTREAM-NOTES.md`）。

`discrate` 保留 beets 的能力，重做它的默认值和交互。

### 一条命令

```bash
discrate ~/Downloads/音乐
```

先出方案，确认后才动手；源文件一个字节都不改；后悔了一条命令撤回。

### 它修正了上游的四个坑

1. **`albumartist` 不继承 `artist`** → 标签齐全的文件被扔进 `Non-Album/`。discrate 显式补齐并标注为「推断」。
2. **无标签文件全部撞到同一个名字** → 三个文件都返回 `Non-Album.mp3`，真执行会互相覆盖。discrate 判为「无法整理」并说明原因。
3. **`Item.destination()` 对专辑型文件选错模板** → `singleton` 查询对 `Item` 恒为真，`paths.default` 永远轮不到。discrate 不用它。
4. **`sanitize_path()` 是给路径片段用的** → 传 `AC/DC` 得到 `AC\DC`（两级目录）。discrate 先转义分隔符再调用。

另外补上了 Windows 保留名（`CON.mp3` 永远建不出来）、尾部点空格、组件长度截断。

### 每个判定都有理由

```
  建议复核（仍会整理，但信息不足，建议确认后再执行）
    同名不同码率\晴天.mp3
      - 从文件名/目录名补全：曲名←文件名
      - 找不到歌手信息，归入「未知歌手」
```

「曲名←文件名」明确告诉你这个字段是推断的，不是文件自带的。

### 四条安全承诺

| 承诺 | 机制 |
| --- | --- |
| 源文件不动 | 默认 copy 模式 |
| 一切可回滚 | 先落 journal 再动手，`undo` 逆序撤回；只删哈希仍匹配的文件 |
| 反复运行不重复整理 | `state.json` 登记 + 跨批次去重，不会产出 `(2)` `(3)` |
| 不覆盖已有文件 | 目标已存在则跳过并说明；同批次撞名自动加编号 |

### 验证

- **157 个 pytest 用例**（Python 3.10–3.13 × Linux/Windows）
- **15 个定向变异体全部杀死** —— 改坏任意一处关键逻辑，测试都会红
- **18/18 项普通用户可用性验证通过** —— 模拟零知识用户只按 README 走：plan → 回车确认 → 检查结果 → 再跑一次 → undo → 重新整理
- 从 wheel 干净安装后跑完整链路（plan / apply / undo）验证通过

### 边界

不联网（不做 MusicBrainz 匹配）、不转码、不处理封面、不拆 CUE。标签写入限定在 6 个字段且不覆盖已有值。详见 `docs/LIMITS.md`。

### 安装

```bash
pip install discrate
```

Python 3.10+，依赖 beets 2.x。首次运行会创建隔离的 beets 配置目录，不读也不改你已有的配置。
